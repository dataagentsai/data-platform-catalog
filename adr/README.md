# ADRs: why the platform is shaped the way it is

**Architecture decision records**, one file per decision, in [MADR 4](https://adr.github.io/madr/) format
(decision D14). DPC says what must exist, DAC what must be true, practices how; an ADR says **why**: the options we
weighed and the one we chose. Recorded once, cited by DPC capabilities (`adr:`), DAC obligations and practices.

## The record

Each file is `ADR-NNN-short-title.md`: MADR's sections (Context and Problem Statement, Decision Drivers,
Considered Options, Decision Outcome with Consequences and Confirmation, More Information) under a YAML front
matter block:

```yaml
id: ADR-003                 # permanent; never reused
status: accepted            # proposed | accepted | deprecated | superseded
date: 2026-11-04
decision-makers: [platform owner]
concerns: [X15, X1]         # core/concerns.yaml
dpc: [DPC-0083]             # capabilities that carry the decision out
dac: [DUP-02]               # obligations the decision serves
plan: [D18, R3]             # plan decisions and rules it records
source: [deck K05]          # where the decision was first argued
superseded_by: ADR-0NN      # only when status is superseded
```

Rules (`scripts/lint.py`, `lint_adrs`): ids unique and matching the file name, known status, the MADR sections
present, every cited concern, capability and obligation exists, no product names (rule R1: a decision that needs a
product names the port, and the binding names the product), and the index below matches the files.
